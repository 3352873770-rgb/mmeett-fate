# 发布流程

## 当前发布状态

当前工作目录尚未记录生产发布流程。

## 授权门槛

除非用户对当前任务明确授权，否则不得发布、部署、合并、打标签、推送或创建公开版本。

## 发布准备

1. 确认发布范围。
2. 确认目标分支和部署目标。
3. 更新 `CHANGELOG.md`。
4. 运行 `npm run check`。
5. 对改动流程执行真实页面 UI 验收。

## Pull Request 流程

如果需要远程协作流程：

1. 创建范围明确的分支。
2. 只提交预期文件。
3. 默认创建 Draft PR，除非用户要求直接进入正式评审。
4. 说明范围、改动文件、检查结果、剩余风险和回滚方式。

## 部署

当前部署方式未知。首次部署前需要记录：

- 托管服务商。
- 构建命令。
- 输出目录。
- 环境变量。
- 公开访问地址。
- 回滚方式。

## 回滚

在部署目标确定前，回滚是指通过 Git 撤销源代码改动，或返回到最近一个确认可用的本地提交。
